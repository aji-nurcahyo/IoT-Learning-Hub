# Panduan bahasa teknis

Gunakan bahasa Indonesia natural untuk penjelasan, modul, slide, latihan, tugas, dan dokumentasi. Judul chapter mengikuti master curriculum. Pertahankan istilah yang lazim: Internet of Things, Microcontroller, Embedded System, GPIO, Sensor, Actuator, Firmware, Gateway, Edge Computing, MQTT, Broker, Publish/Subscribe, QoS, Device Provisioning, OTA Update, Time-Series Database, Digital Twin, RTOS, TinyML, dan Deployment.

Pada pemakaian pertama, jelaskan istilah melalui fungsi atau contoh. Contoh: “Broker menerima pesan dari Publisher dan meneruskannya kepada Subscriber yang sesuai.” Hindari menerjemahkan identifier API, nama file, flag CLI, atau nama protokol.

Gunakan tujuan terukur: “Membandingkan QoS 0 dan 1”, bukan “Memahami MQTT”. Bedakan instruksi, output yang diharapkan, output aktual, data sintetis, dan analisis. Jangan menulis “hasil menunjukkan” tanpa eksperimen nyata. Sertakan unit setiap nilai fisik; bilangan di source code mengikuti sintaks bahasa.

Status resmi: Belum diuji, Compile-verified, Simulator-verified, Hardware-verified. Status publikasi: Coming Soon dan Tersedia. Status resource: tersedia, direncanakan, tidak relevan dengan alasan eksplisit. Jangan menerjemahkan Coming Soon sebagai bukti materi sebagian telah teruji.

Hindari jargon tanpa konteks, klaim berlebihan, atau gaya terjemahan kata-per-kata. Gunakan “jalankan”, “catat”, “bandingkan”, dan “periksa”. Rujuk datasheet dengan model/revisi tepat; tidak ada “pin ESP32 standar” yang diasumsikan berlaku untuk semua board.
